### Bounded initial metric proposal (#104)

| Instrument | Proposed meaning and bounded dimensions |
| --- | --- |
| `marketplace_listing_transitions_total` | Actual create/approve/reject/sold/remove transitions, bounded result. |
| `marketplace_listing_operation_duration_seconds` | Duration in seconds, bounded operation/result. |
| `marketplace_photo_uploads_total` | success/rejected/error outcomes. |
| `marketplace_photo_upload_bytes` | Histogram of accepted bytes only. |
| `marketplace_reports_total` | accepted/duplicate/rejected outcomes. |

Before implementing, define enumerated label values, histogram buckets, units and exact event timing. Count successful persisted transitions once per actual transition; invalid/unauthorized requests, failed transactions, retries and idempotent operations must follow documented semantics. Verify bucket/count and label upper bounds under errors, rollback, retries and concurrent conflicts. Document worker aggregation, resets and that process counters are not durable transactional totals. Record low-traffic baselines/denominators; expansion requires PM grooming. No user/listing/report IDs, email, free text or unbounded categories.

### Signal privacy, reliability and agent boundaries

Allowlist templated routes and bounded outcome/status classes. Never export credentials, authorization/cookies/tokens, PII/email/identifiers, query strings, raw paths, bodies, SQL parameters or captured exception payloads. Test malicious/private canaries absent across all three stored/exported signals and dashboard/alert/agent evidence. Use bounded cardinality and service/environment/version correlation rather than identity labels. Pin minimal compatible implementation dependencies/Collector and document maturity/version decisions when actually selected; this roadmap selects no storage stack or versions.

Bound queue/batch/memory/sampling/retention and query/result limits; use private binding and appropriate auth/TLS. Outage must not hang requests, exhaust memory or expose telemetry. Measure overhead/loss and collection failures; do not default to broad unsafe capture.

The AI provider/model/execution location is unchosen. Before real inference the owner must explicitly select it, the credential destination, allowed redacted data/egress, cost/token budget and authorized human escalation destination. Cloud/SMTP/SSH credentials never enter model context. Unknown provider/destination fails closed. Redact before calls; telemetry is untrusted, so log/prompt injection cannot override policy or cause egress. Test canaries, evidence references, retention/access/audit, model/tool outages, bounded retries, wall-clock/tool/query/result/token/cost/concurrency limits, incident fingerprints, dedupe/idempotence, cooldown and durable incident state. No shell, arbitrary URLs, deploy/DB write access or autonomous remediation. Only human-approved actions may mutate production. Escalations remain local until separately authorized.

## Decisions, capacity and authorization gates

Local disposable rehearsals come first when their implementation issue is advanced; reversible isolated tests do not themselves require a new approval. This step authorizes documentation only. Choose tools and pin minimal dependencies during the groomed implementation, rechecking official documentation rather than treating this roadmap as compatibility validation.

The last documented Oracle ARM sizing is **1 OCPU / 6 GB RAM** (see [Oracle operations](oracle-demo.md)); this planning step did not remeasure host resources. #101 must measure representative app + DB + Collector + candidate telemetry storage/dashboard CPU, RAM, disk growth, queue and retention on a documented local host, then project realistic host headroom and explicit stop thresholds. Choose the smallest measured viable arrangement, or report hosted capacity blocked. No measurement here guarantees a heavy stack fits, free eligibility, zero cost or production scale. #90 retains broader app/DB resource and recovery safeguards.

Before hosted activation: review actual destination contracts (#56/#88/#89 where applicable), #90 safety, #87 platform-tested image identity, capacity, backup/recovery and exact host/resource/access/URL/DNS/security/secret transition consent. Preserve current controller/site/data until that transition; destructive live drills are excluded. Any brief downtime rehearsal needs specific authorization. No new resources or paid services follow from planning.

Alerts initially go only to an isolated local test receiver with bounded environment/service/version, severity, time, runbook and dashboard/evidence links, without private payloads. Before external delivery the owner must specify exact destination/recipient/channel, allowed data and message/rate budget. Provider credential/data egress and actual AI inference have their separate gate above. No external notification, teacher contact or third-party submission is authorized here.
